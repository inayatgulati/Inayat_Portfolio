Overview

The Problem &
The Solution

Travel planning is fragmented. Users rely on separate apps to search places, save ideas, plan schedules, and document experiences — making the process overwhelming and disconnected.

6+
Apps for one trip
Maps, notes, calendar, camera, booking, journaling — all separate, none talking to each other
Context loss
Switching kills flow
Every app switch breaks the planning mindset — users lose track of where they were and what they were doing
Memories lost
No reflection layer
Photos end up in camera rolls, notes in random apps — no structured way to look back on a trip

"Design a unified mobile travel experience that reduces cognitive load by seamlessly connecting discovery, trip planning, and reflection within a single, intuitive interface."

Chemtrails unifies exploration, planning, and reflection into one intuitive mobile experience. Users can search places, save destinations into folders, schedule visits using a calendar, and journal memories with photos — all within the same app.

1
Design Concept

Calm · Exploratory
Personal

Chemtrails is designed to feel like a travel companion, not a task manager. The interface uses soft colour tones, clear hierarchy, and generous spacing to minimise cognitive load.

🎨
Content is the hero
Place images, maps, and journal photos remain the focal point — the UI stays intentionally minimal and supportive rather than decorative.
🧘
Reduced cognitive load
Generous spacing, clear information hierarchy, and predictable navigation patterns let users focus on where they're going, not how to use the app.
✈️
Exploration-forward
Every screen encourages wandering — from rotating travel quotes on the home screen to discovery-first search results that surface places before logistics.
2
Colour Palette

Inspired by Travel,
Nature & Movement

The palette is built around calmness and clarity — soft blues and muted greens evoke openness, reliability, and exploration without overwhelming the content.

🔵
Primary — Soft blues
Evoke openness and reliability. Used for primary actions and key navigation elements across all screens.
🌿
Secondary — Muted greens
Suggest nature and exploration. Used for supporting surfaces and secondary interface elements.
⬜
Neutral tones
Support backgrounds and secondary surfaces — keeping place images, maps, and journal photos as the visual focus.

Accent colours are used sparingly for primary actions (saving a place, adding a journal entry) to guide user attention without overwhelming the interface. A restrained palette reduces visual fatigue, supports long browsing sessions, and lowers cognitive load during planning-heavy tasks.

Challenges & Learning

First Full
Mobile App

This was my first full mobile app built with React Native. The hardest parts weren't the design — they were the gaps between design and working code.

🧭
Navigation state management
React Native's navigation stack required careful state handling — especially when passing data between screens like a selected destination flowing into the calendar and wishlist.
📸
Image uploads and storage
Connecting Firebase Storage with camera and gallery permissions across iOS and Android exposed platform-specific differences that documentation alone couldn't fully prepare for.
🔌
API error handling
Google Places API responses required robust error handling — rate limits, empty results, and network failures all needed graceful fallbacks to avoid crashes in production.
📅
Calendar logic
Building a custom calendar that synced with Firestore in real time — handling date conflicts, multi-day trips, and timezone differences — was the most technically demanding part of the project.

"Through documentation-driven learning, debugging, and iteration, I gained confidence in building scalable, multi-screen mobile applications and translating UX designs into functional products."
